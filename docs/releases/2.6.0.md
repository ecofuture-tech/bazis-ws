# bazis-ws 2.6.0

Requires Bazis 2.4.

## Publishing

- `bazis.contrib.ws.messages` publishes the messages of bazis-front (`@/bazis/react/ws`)
  from the code of a write, after the commit of the current transaction (at once outside a
  transaction) and robustly (Redis down does not fail a committed write):
  - `notify(users, message)`: the message built by `message(user)` for each user (a user or
    an iterable; `None` and repeated users skipped), built and serialized in the language of
    the user (`user.language` of `UserLanguageMixin` of bazis-users, or `LANGUAGE_CODE`), so
    lazy strings are translated per recipient;
  - `notification(title, text=None, item=None)`: `{"action": "notification", "title",
    "text", "resource", "id"}`;
  - `publish_changed(item)`: `{"resource": "<JSON:API type>"}` on the common channel,
    without the id.

  The trial projects wrote this notifier by hand (a Redis client, `on_commit`, the language,
  the format); the guide now uses the helpers instead of the manual recipe.

## Setup

- `router.register('bazis.contrib.ws.router')` registers the socket in the router module of
  the project (`BS_BAZIS_ROUTER_MODULE`), like the routers of the apps. The socket is routed
  under the prefix of the router: `/api/v1/ws` under `BazisRouter(prefix='/api/v1')`. The
  contract export of bazis-front finds it and its path there. The guide, the README and the
  sample use it instead of `router.routes.append(ws_route)`.

## Compatibility

- `ws_route` is unchanged: a project that appends it keeps the path `/ws`. Moving to
  `router.register('bazis.contrib.ws.router')` changes the path of the socket to
  `<prefix>/ws`: clients that do not take the path from the contract of bazis-front
  (bazis-front does) must use the new path.

# bazis-ws 2.3.0

Requires Bazis 2.3 (Django 6.1, FastAPI 0.142).

## Security

- **An anonymous client could read the channel of any user.** A token that is not a JWT
  was used as the channel name as is, so sending `{"token": "user_ws::42"}` subscribed
  to the personal channel of the user 42. Anonymous channels are now `user_ws:anon:<token>`,
  and an anonymous token must be 16–128 characters `A-Z a-z 0-9 _ -`; other tokens are
  rejected with `invalid_token`.
- Inactive users can no longer open a session (`user_not_found`).
- The session JWT must contain `exp` and `sub` (a token without expiration was accepted).
- `python-jose` (unmaintained, with known vulnerabilities, and no longer installed by
  Bazis) is replaced with `PyJWT`. Existing tokens stay valid.
- Tokens and message contents are no longer written to the log.

## Fixes

- Closing a socket took up to 5 seconds and logged errors: the background tasks are now
  cancelled instead of waiting for their next iteration.
- If Redis fails during a session, the socket is closed with code 1011 so that the
  client reconnects; before, the client stayed connected without receiving messages.
- The asyncio Redis client is created per event loop instead of at import time.
- The user is read with the libpq parameters of the Django database: an empty `HOST`
  stays empty (the Unix socket), the libpq options of `OPTIONS` (e.g. `sslmode`) are
  passed and the options of the Django backend (`isolation_level`, `server_side_binding`,
  `pool`) are not; with a connection timeout and a properly quoted table name.
- Logging goes to the `bazis.contrib.ws.*` loggers instead of the root logger.

## Breaking changes

- Anonymous channel names changed (see above); publishers must use
  `bazis.contrib.ws.utils.get_anonymous_channel(token)`. bazis-async-background 2.3.0 does.
- `WsEndpoint.running_check()` is removed and `is_running` is a read-only property.
- New dependencies: `PyJWT`, explicit `psycopg` and `redis`.

The sample project received the migration for the `AbstractUser` changes of Django 6.
CI runs the tests on Python 3.12–3.14 and with the lowest allowed dependency versions;
releases are made with the Release workflow (see `CLAUDE.md`).
